# 横拍转竖屏 9:16 裁切工作台

横拍的手工课素材改竖屏：在**原图内按原高**裁出 9:16 竖窗，保证手与工件（逐帧必留框）
始终完整留在画面里，并让裁切轨迹在时间上尽量平滑、画面信息量尽量大。

## 功能

- 上传至多 **80 张**有序、同尺寸 PNG 帧 + 逐帧必留框 JSON（帧边长 ≤ 512，高为 16 的倍数）。
  上传只做 PNG 解码与必留框校验，**不做任何灰度差计算**。
- 每帧裁切窗高 = 原图高 H，宽 = 9H/16，仅横坐标 x 可变；每帧窗口**覆盖全部必留框**。
- 轨迹约束：相邻帧横移 `|Δx| ≤ 8`；连续两次有向横移之差 `|Δxᵢ₊₁ − Δxᵢ| ≤ 2`。
- 求解分两步：
  1. **布尔可达性 DP**（只用可行掩码与锁定，不碰灰度）先判断整段能否接成一条完整合法
     轨迹，并求出每帧能出现在某条完整合法轨迹上的窗口（**可达窗**）。无解时立即返回
     从首帧起最早接不上的帧，撤下竖屏预览，**整轮不算灰度差**。
  2. 有解时**只给可达窗评分**：水平相邻像素对仅当两列同被某个可达窗覆盖、竖直相邻像素对
     仅当该列被某个可达窗覆盖时，才计算一次灰度差；同一轮、同一帧每对像素最多算一次，
     列差经前缀和复用给各窗。不可达窗能量置 0，不参与选择。
- 评分后的能量再交给二阶数值动态规划求全局最优；**轨迹、总能量与同分选法与旧版一致**。
- 改锁/解锁后按新的可达范围重新做可达性与评分（可达窗越少，灰度差计算量越小）。
- 逐帧查看裁切结果（原图 + 可达取景区间 + 裁切窗 + 9:16 竖屏预览），可**拖动**裁切窗并
  **锁定/解锁**任一帧；改动某一帧锁定位置后重新求解，前后未锁定帧自动跟着调整。
- 若接不出完整轨迹，报告**从首帧起最早接不上的一帧**，跳到该帧原图并撤下竖屏预览。
- 内置两段样片：A（可解）、B（第 12 帧工件瞬移，演示不可解）。

## 必留框 JSON 格式

```json
{
  "frames": [
    [[x0, y0, x1, y1], ...],
    ...
  ]
}
```

- 顶层也接受裸数组（等价于 `frames` 的值）。
- 长度必须等于帧数；每帧可为空数组（该帧无必留框）。
- 框为像素区间 `[x0, x1) × [y0, y1)`，须在画面内。裁切窗高为整帧高，故只有 x 方向影响可行性。
- 上传多帧时按文件名自然序排列（frame_2 在 frame_10 前）。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/upload` | multipart：`frames`（多个 PNG）+ `boxes`（JSON 文件），仅校验不评分 |
| POST | `/api/load_sample?name=a\|b` | 载入内置样片 |
| POST | `/api/solve` |  body `{"locks": {"帧号": x}}` → 轨迹或 `fail_frame` |
| GET  | `/api/frame/{i}.png` | 第 i 帧原图 |
| GET  | `/` | 单页应用 |

`/api/solve` 响应：

- 成功：`{ok: true, trajectory: [...], energy, reachable: [[lo, hi, 窗数], ...],
  pair_count, h_pairs, v_pairs, full_pair_count}`，其中 `pair_count` 是本轮实际计算
  灰度差的相邻像素对总数，`full_pair_count` 是旧全量评分一轮的对照基准。
- 失败：`{ok: false, fail_frame, message, pair_count: 0, full_pair_count, reachable: null}`。

## 实测结果（本机，24 帧 512×288 样片）

- 样片 A 无锁：可达窗 21–119 个/帧（全量 351 个/帧），本轮计算 **3,431,013** 对像素差
  （水平 1,715,040 / 竖直 1,715,973），全量基准 7,058,688，**少算 51.39%**；
  锁帧 0 后计算量进一步降到 3,389,613，轨迹/总能量与旧全量路径逐场景一致。
- 样片 B（第 12 帧瞬移）：可达性 DP 在帧 12 判定接不上，`pair_count = 0`，前端跳到帧 12
  并撤下竖屏预览。
- 随机 60 组小例：布尔可达掩码与暴力枚举的合法轨迹横坐标集合逐位一致；新旧路径在 16 个
  锁定场景下轨迹、总能量、同分选法完全相同。
- 最坏规模（80 帧 512×512、224 个窗位）求解约 1.6–1.8 秒，峰值 RSS ≈ 86MB。

## 已知限制

- 单会话：服务端只保存一份当前工程，多人同时用会互相覆盖（演示定位）。
- 帧数据全在内存：80 帧 × 512×512 灰度约 21MB，实测峰值 RSS ≈ 86MB，可接受。
- 最坏规模（80 帧、x 取值 224 个）求解约 1.6–1.8 秒；常规规模亚秒。
- 裁切窗垂直位置固定（按原高裁切），只有水平自由度。
- 灰度差计算量统计的是实际执行 `|Δ|` 的相邻像素对；前缀和聚合属于加法复用，不计入。
